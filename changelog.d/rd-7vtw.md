### Added

- `accessible_label` and `accessible_description` on every element, of every type, in a document of either `schema_version`: each optional and each a template in the subset. `accessible_label` is the name an assistive technology gives the element where its visible text is not enough, and `accessible_description` a longer account it may read after the name. Each is rendered at resolve, a missing variable reported under the element's key, and the resolved and presented element carries each only where the document wrote it. A `variant` carries its winner's pair, not its own.
- The refusals these fields bring: `document.invalid_template` for an accessible field that is not a string or holds a construct outside the template subset, and `document.secret_reference` for one that names a secret question's response. A document that uses neither field is admitted, validated, resolved and presented as before. A document written for 0.8.0 that already carried either field had it dropped at admit; it is now read, rendered, and refused as above where it is not a template.
- The screen document schema describes both fields on every element and types neither, so a value that is not a string is the finding above against an admitted document. The presented-answer schema types both as strings on every type it enumerates; an answer carrying either still validates against an earlier release's schema.
