### Added

- A question may carry `checks`, a list of conditions its author writes, each an object of a predicator `condition` over `context` and `responses`, an author's `code` in the `check.` namespace and a plain-string `message`. Every question type takes it. Response validation evaluates a shown question's checks after its built-in checks, against the root an element's condition reads, so no check reads a secret question's response: the first check the root decides false raises one finding, its `code` the check's, its `field` `"checks"`, its `author_message` the check's `message`, and a `message` that quotes no response. A question a condition hid, a question the built-in checks already refuse, and a question whose response is nothing answered have none of their checks evaluated.
- A check the root does not decide raises no finding and is reported in a third list of the diagnostics, `undecidable_checks`, an entry of the question's `key`, the check's `code` and its `condition`, on what `resolve/2`, `resolve_screen/3` and `Riddler.Journey.present/3` answer. The key is there only where it holds an entry, so a screen with no check, or none undecided, resolves and presents exactly as before. The presented-answer schema names it as an optional property, and no resolved or presented question carries `checks`.
- The refusals checks bring: `document.invalid_check`, its `field` `"checks"`, for `checks` on an element that is not a question, `checks` that is not a list, an entry that is not an object or lacks a `condition`, `code` or `message`, a `code` outside the `check.` namespace (a code this package raises included), a `message` that is not a string or is empty, and a `code` another check on the same question already carries; and `document.invalid_condition` and `document.secret_reference`, their `field` `"checks"`, for a check's condition that is not a string, does not parse, or reads a secret question's response.
- A host whose documents already carry a `checks` key, which riddler 0.8.0 dropped on every element: a well-formed `checks` on a question is now enforced when a response is validated, and any other `checks` is now refused by `Riddler.Screens.Document.validate/1`. Remove a `checks` key a document does not mean, or write it in the shape above.
