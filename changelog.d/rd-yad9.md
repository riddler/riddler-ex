### Changed

- A resolved or presented `text_question`, `choice_question` or `boolean_question` node carries `value`: the response the root holds for it, as written, else the value its new `prefill` path reads from `context`, else its new `default`, each of those two only where it is of the question's response shape (and, on a choice question, among its options); a node none of them yields one for carries no `value`, and a resolved node never carries `default` or `prefill`. A host that resolves a screen whose root already holds responses now sees them as `value` on `Riddler.Screens.resolve/2`, `Riddler.Screens.resolve_screen/3` and `Riddler.Journey.present/3`. `value` is not a response: `validate_screen/3,4` still reads only the responses the root holds.
- A `default` or `prefill` on a text, choice or boolean question, which 0.4.0 admitted and dropped, is now read, and `Riddler.Screens.Document.validate/1` refuses one that is malformed: `document.invalid_default` for a default not of the question's response shape or naming a value none of its options carries, `document.invalid_context_path` for a prefill that is not a dotted path of key-shaped segments under `context`. Fix such a document by correcting the field or removing it.
