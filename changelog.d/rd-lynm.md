### Added

- `style` on a `text_question`, a hint a renderer owns: `multiline`, a field for more than one line of text, and `slider` and `stepper`, read with the `integer` and `number` formats, are the names offered. The hint stays open: any string is passed through to the renderer, and a renderer that draws no slider or stepper draws the field it would draw with no `style`.
- `step` on a `text_question`, a hint for the increment a slider or a stepper moves by, read only with the numeric formats: with `integer` an integer above zero, a number with no fractional part counting as one, and with `number` a number above zero. With any other format, or none, a `step` that is a number is consulted by nothing, and one that is not a number is refused. Response validation does not read it: a response between the bounds is accepted whatever the step. The resolved and presented question carry `style` and `step` where the document wrote them.
- The refusals these fields bring: `document.invalid_style` for a text question's `style` that is not a string, and `document.invalid_step`, its `field` `"step"`, for a `step` that is not a number, whatever the format, and for one under the `integer` or `number` format that is not a number above zero, or, under `integer`, has a fractional part. A document that uses neither field is admitted, validated, resolved and presented as before. A document written for 0.8.0 that already carried either field on a text question had it dropped at admit; it is now kept, and refused as above where it is not in its shape.
- The presented-answer schema types a text question's `style` as a string and its `step` as a number. An answer carrying either still validates against an earlier release's schema.
