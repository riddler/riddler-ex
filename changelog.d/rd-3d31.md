### Added

- The `image` element type, in a document of either `schema_version`: a required `src` and a required `alt`, a template whose empty string marks the image decorative, and the optional hints `size` and `fit`, which a renderer reads. A screen that uses no image resolves and validates as before.
- One URL rule for an image's `src`: an `https://` URL naming a host, a host-relative URL beginning with a single `/`, or, written in the document itself, a base64 `data:` image of type `image/png`, `image/jpeg`, `image/gif` or `image/webp` of at most 65,536 bytes. Any other scheme, `http:`, `javascript:` and `data:image/svg+xml` among them, is refused, as is a URL carrying whitespace, a control character, template syntax, or, in an `https://` URL, a backslash; nothing is trimmed or rewritten.
- A `src` beginning `context.` is a path, read from the context when the image is shown; where it reaches no `https://` or host-relative URL, the image is left out of the resolved screen and the path, never the value, is reported in `missing_variables`.
- The refusals an image brings: `document.invalid_url` for a literal `src` the rule refuses, `document.invalid_context_path` for a `src` beginning `context.` that is not a path under it, `document.invalid_hint` for a `size` or `fit` that is not a string, `document.invalid_template` for an `alt` outside the template subset, and `document.missing_field` for an image without `src` or `alt`.
- The presented-answer schema enumerates `image`, requiring its `key`, `src` and `alt` as strings and typing `size` and `fit` as strings. An answer carrying an image still validates against an earlier release's schema, and a client built to it does not render the image.
