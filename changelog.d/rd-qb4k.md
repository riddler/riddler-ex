### Added

- The `divider` element type, in a document of either `schema_version`: a rule between the elements around it, carrying no field of its own; it resolves to its `type` and `key`.
- The `link` element type, in a document of either `schema_version`: a required `label`, a template, a required `href`, and an optional `style` hint, `inline` and `button` being the names offered. A link raises no outcome: an `outcome`, `writes` or `validates` written on one is dropped at admit, and a presented screen never lists a link among its `outcomes`.
- A link's `href` is held to the image's URL rule with no `data:` form: an `https://` URL naming a host or a host-relative URL beginning with a single `/`, and nothing else. An `href` beginning `context.` is a path, read from the context when the link is shown; where it reaches no such URL, the link is left out of the resolved screen and the path, never the value, is reported in `missing_variables`.
- `style` on a `text`, a hint a renderer owns: `body` and `caption` are the names offered, and a text with none is `body`. A text with no `style` resolves with none.
- The refusals a link, a divider and a text style bring: `document.invalid_url` for a literal `href` the rule refuses, a `data:` URL among them; `document.invalid_context_path` for an `href` beginning `context.` that is not a path under it; `document.invalid_style` for a link's or a text's `style` that is not a string; `document.invalid_template` for a link's `label` outside the template subset; and `document.missing_field` for a link without `label` or `href`. A divider brings none of its own. A document that uses none of these types or fields is admitted, validated and resolved as before.
- The presented-answer schema enumerates `divider` and `link`, requiring a divider's `key` and a link's `key`, `label` and `href` as strings, and types a link's and a text's `style` as strings. An answer carrying either type still validates against an earlier release's schema, and a client built to it does not render that element.
